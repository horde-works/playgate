# Параллельная работа: две машины и соседние агенты

Над этим репозиторием одновременно работают **две машины** и **несколько
сессий на каждой**. Почти всегда в рабочем дереве лежит чужая незакоммиченная
работа, а `origin` уезжает вперёд посреди твоей задачи. Это норма, а не авария.

Соседние плейбуки (читать в дополнение, не вместо):

- **git в общем дереве, запрещённые команды, отделение своей поломки от чужой**
  — `games/make-a-mess/docs/shared-tree-discipline.md`. Он владеет темой
  целиком; здесь она не пересказывается;
- **как получить наблюдение** (запуск, кадр, гигиена браузера) —
  `games/make-a-mess/docs/run-and-verify.md`;
- **протокол машин и список принятых красных тестов** — `CLAUDE.md` в корне.

Связь — SSH поверх Tailscale. Вход на Windows ведёт **не в Windows напрямую, а
в WSL-дистрибутив `Debian`**: штатный windows-sshd не умеет строить токен для
Entra-учётки (`AzureAD\...`, ошибка 1355) и потому отключён. Внутри WSL обёртка
`winrun` переносит команду в нативный windows-процесс, поэтому штрафа `/mnt/c`
на сборке нет.

## 2. Куда отправить задачу

Деление идёт **по весу задачи, а не по ролям машин**. Обе машины полноценно
правят код.

На **Windows** уходит всё длинное и тяжёлое: полный прогон, `next build`,
`next dev` со съёмкой кадров, широкие правки на много файлов, аудиты по всем
сценам, несколько параллельных worktree.

На **Mac** остаётся работа поуже: проектирование, ревью, документы, точечные
правки. Там 8 ГБ памяти и почти забитый диск, поэтому `npm ci`,
`npm run build`, полный `npm test` и `next dev` локально не запускают.

**Mac не отказывается от тяжёлого, а передаёт его.** Отказ «у меня не хватит
памяти» — неверный ответ; верный — отправить на Windows и дождаться.

## 3. Как передать работу

### Команда на Windows

```
ssh igor@100.108.230.70 "winrun npm test"
ssh igor@100.108.230.70 "winrun npx tsc --noEmit"
```

`winrun` выполняет команду в корне репозитория Windows-копии.

### Целая задача на Windows

```
ssh igor@100.108.230.70 "winrun claude -p 'задача'"
```

На Windows учётные данные лежат файлом, поэтому headless-агент там работает.
Туда передают не только прогоны, но и **задачи по коду целиком** — они как раз
тяжелее и длиннее.

### Разговор с агентом на Mac

Обратное **невозможно напрямую**: на Mac учётные данные в Keychain, недоступном
неинтерактивной сессии, и `claude -p` по SSH падает с `Not logged in`. Правка
списка разделов Keychain (`security set-generic-password-partition-list`) эту
проблему НЕ решает — проверено, остаётся `errSecInteractionNotAllowed`. Не
тратить на это время.

Вместо этого работает почтовый ящик. Сторож `~/bin/mac-agent-watcher.sh`
запускается **из Terminal.app** (не по SSH — в этом весь смысл, процесс должен
унаследовать GUI-сессию):

```
screen -dmS macagent ~/bin/mac-agent-watcher.sh
```

Дальше обмен файлами:

```
scp вопрос.txt kirisyuk@100.74.187.80:.agent-mailbox/ask.txt
ssh kirisyuk@100.74.187.80 'cat ~/.agent-mailbox/answer.txt'
```

Перед новым вопросом удалять старый `answer.txt`, иначе прочитаешь прошлый
ответ. `~/.agent-mailbox/watcher.log` показывает, взят ли вопрос в работу.
Сторож не переживает перезагрузку — если ответа нет и лог молчит, он просто не
запущен.

**Что писать в письме.** Агент на той стороне не видит твоего контекста:
он не знает, что ты уже сделал, на каком ты коммите и почему спрашиваешь.
Письмо без этого возвращает вежливую пустоту. Давать: текущий коммит, что уже
проверено и чем, что именно нужно от него, и чего делать НЕ надо.

## 4. Главная ловушка: рабочих копий две

`winrun` работает в файлах Windows, а не в твоих. **Незапушенная правка для
него не существует** — прогон пройдёт по старому коду и вернёт зелёный, ничего
не проверив. Это самый дорогой способ обмануть себя в этой схеме.

Перед передачей тяжёлого прогона: закоммитить, запушить, на той стороне
`git pull`. Если прогон нужен по незакоммиченному — гнать его на своей машине
или не гнать вовсе.

## 5. Две сессии на одной машине

Разводить по **подсистемам**, а не по принципу «кто успел»: мир / транспорт /
жители / разрушение / окружение. Пересечение по файлу — источник половины
потерь.

Когда нужна изоляция, каждой сессии свой worktree:

```
git worktree add ../playgate-<задача> <ref>
```

Помнить: `node_modules` между worktree не разделяются, каждому нужен свой
`npm ci` (около 0.5 ГБ). На Windows это терпимо, на Mac — нет.

Всё, что касается `git` в общем дереве — запрещённые команды, снятие baseline,
один файл на двоих, откат чужой правкой — в
`games/make-a-mess/docs/shared-tree-discipline.md`. Там же объяснено, чем
оплачен запрет на `git stash`.

## 6. Приём чужой работы

1. `git fetch`, посмотреть, что приехало: `git diff --stat <было>..<стало>`.
2. Свои коммиты ставить **поверх** через `git rebase origin/main`, а не
   вливать встречным merge.
3. Прогон после слияния обязателен, если пришёл код. Если пришли только
   документы — не обязателен, и честнее сказать об этом, чем гонять зря.
4. Сверять не «зелено ли», а **тот ли набор красных**. Поимённый список
   принятых красных — в `CLAUDE.md`. Любой не из списка — регрессия.
5. Число тестов растёт с каждым коммитом: сравнивать имена, а не счётчики.

## 7. Взаимные помехи, которые выглядят как баги

- Широкий `pkill -f headless` убивает браузеры соседних агентов
  (`run-and-verify.md`).
- Не мерить FPS, когда рядом идёт чужой прогон или сборка
  (`performance-lessons.md`).
- Не гонять сборку параллельно с тестами: тест рендера страницы делает
  собственный production-рендер в тот же каталог.
- Ошибки вида «не воспроизводится у меня» на разных машинах чаще всего
  платформенные, а не случайные. Уже ловили: загрузчики скиллов разной
  строгости к YAML (скилл терял все триггеры на одной машине и грузился на
  другой), `sips` вместо кроссплатформенного инструмента, пути Chrome без
  проверки существования, тайпчек, уходящий в `out/`.

## 8. Чеклист перед долгой параллельной работой

- [ ] Синхронизирован с `origin`, знаю, кто ещё работает над этой подсистемой
- [ ] Задача на той машине, которой она по весу
- [ ] Если передаю прогон — правки запушены, на той стороне сделан `pull`
- [ ] Свои файлы не пересекаются с чужой активной подсистемой
- [ ] Прочитан `shared-tree-discipline.md`, если предстоят git-операции
- [ ] После слияния сверил имена красных тестов со списком в `CLAUDE.md`
- [ ] Свою незакоммиченную работу не держу дольше, чем нужно: вторая машина
      её не видит
