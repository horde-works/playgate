# Общее рабочее дерево: git, соседние агенты, чужие поломки

Над этим репозиторием одновременно работают несколько агентов и автор. В
рабочем дереве почти всегда лежит **чужая незакоммиченная работа**. Из этого
следуют правила, которые дороже любых удобств.

Док владеет дисциплиной работы в общем дереве. Что запускать и как проверять —
`run-and-verify.md`. Протокол машин и список принятых красных тестов —
`CLAUDE.md`.

---

## 1. Команды, которых не существует

Не выполнять **никогда**, ни в каком виде, ни ради «чистого baseline»:

```
git stash            git checkout -- .
git reset --hard     git clean
git add -A
```

Единственная разрешённая форма — `git stash list`, без редиректов и без
сокращений.

**Чем это оплачено.** `git stash` ради baseline полного прогона: прерывание
пришло между `stash` и `stash pop` — **185 файлов** чужой незакоммиченной
работы (польдер, мельницы, SR-6, объект гексакоптера, доки и манифесты)
исчезли из дерева на несколько часов. Восстановилось только потому, что
`stash@{0}` уцелел. Второй раз слово `git stash` проскочило **опечаткой**
(вместо `git stash list`, ещё и с `>/dev/null`) и на секунды спрятало 17
файлов, включая живую работу соседа. Отсюда запрет на голый токен, а не на
«неосторожное использование».

`git add -A` затаскивает в коммит чужие незаконченные файлы: работа агента
деревьев однажды уехала под чужими сообщениями о полёте. Добавлять **только
явным списком своих файлов**.

## 2. Если baseline действительно нужен

Сначала спросить себя, **просил ли кто-нибудь полный прогон вообще**. Чаще
всего требование придумано из чек-листа скилла, а не задачей.

Если нужен — делать на копии: `git worktree add` во временный каталог. Живое
дерево не трогать ни при каких условиях.

## 3. Как отличить свою поломку от чужой

- Читать **имена** упавших тестов и проверять, задевают ли они твои файлы.
  Этого почти всегда достаточно, и это ничего не стоит.
- Смотреть `git status`: чужие файлы в дереве и `HEAD`, уехавший вперёд
  посреди работы, — прямой признак активного соседа.
- Чужие поломки выглядят как настоящие и проходят сами: за один день это были
  `arrivalPresentationPhase is not defined` и TDZ на `resolveCarveTarget` —
  обе валили сцену целиком.
- Красный тест из списка принятых (`CLAUDE.md`) чинить не нужно. Любой другой
  красный — регрессия.
- Не чинить чужое без просьбы. Наблюдать фоном и ждать.

## 4. Один файл на двоих

Явного списка файлов мало: сосед правит тот же `MakeAMessGame.tsx`, и
`git add <файл>` утащит его ханк.

Рабочий приём:

1. `git diff <файл> > p.patch`;
2. выкинуть чужие ханки по заголовку `@@ -<строка>`;
3. `git apply --cached p.patch`.

Патч **обязан оканчиваться переводом строки**, иначе `corrupt patch`. Свои
ханки опознавать **по содержимому**, а не по номерам строк: строки уезжают от
чужих правок выше.

## 5. Чужая правка может откатить твой файл целиком

Два файла в середине сессии вернулись к состоянию `HEAD` вместе со всей
работой в них, и следующая правка легла уже поверх отката. Сигнал — знакомая
функция «не экспортируется», хотя её только что добавили.

Отсюда: держать копию своих файлов в scratchpad и обновлять её после каждого
закрытого куска; при странной ошибке компиляции сперва грепать **свои маркеры**
в файле, а не искать баг в коде.

`Edit`, сообщающий «file had been modified on disk», — это не сбой инструмента,
а сообщение о том, что сосед работает прямо сейчас.

## 6. Ветка тоже общая

`git checkout -b` уводит на новую ветку и соседнюю сессию вместе с её
несохранённой работой. Ветку не переключать без нужды и без предупреждения.

Коммит «всего» неизбежно заметает чужое незавершённое. Если этого не избежать —
называть заметённое явно в теле сообщения.

## 6А. `node_modules` тоже общий, и worktree его не получает

`git worktree add` даёт рабочую копию БЕЗ зависимостей, и первое желание —
подцепить общие junction'ом (`mklink /J`). Так делать нельзя.

Замер собственной ошибкой (10.08.2026): baseline-worktree с junction на
`node_modules` основного дерева, затем `git worktree remove --force` — и уборка
прошла ПО ССЫЛКЕ ВНУТРЬ. Из общего `node_modules` осталось 67 каталогов из 336:
снесло `react`, `react-dom`, `@dimforge/rapier3d-compat`, tailwind. Соседняя
сессия при этом работала.

Починка оказалась дороже ошибки. `npm ci` упал дважды: сперва `EPERM` на
`lightningcss.win32-x64-msvc.node` (нативный файл держал процесс соседа), потом
`ENOTEMPTY` на `node_modules/next/dist/api`. `rm -rf` на Windows не дочищает —
нужен `cmd /c rmdir /s /q node_modules`, и только после этого `npm ci` проходит.
`npm ci` при этом добавляет в лок строку `"hasInstallScript": true` — её надо
снять, иначе лок уедет.

Отсюда правила:

- **junction на `node_modules` не создавать никогда**. Если worktree нужен
  рабочим — ставить в него зависимости отдельно, либо не собирать в нём вовсе;
- **worktree для baseline-замера держать read-only**: сравнивать поведение можно
  и запуском из основного дерева на `git stash`-свободной копии файла;
- перед `worktree remove --force` убедиться, что внутри нет ссылок наружу.

## 7. Гейт перед пушем

Сборка + `tsc --noEmit` + полный прогон тестов.

**Не гонять сборку параллельно с тестами**: тест рендера страницы делает
собственный production-рендер в тот же каталог сборки и даёт два ложных
падения.
