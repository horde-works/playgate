# Документация make-a-mess: как она устроена

Документация живёт в два слоя, и у каждого своя роль:

- **Скиллы** — `.claude/skills/*/SKILL.md` — рабочие процессы. Агенты читают
  их по триггерам ПЕРЕД правкой соответствующего домена. Скилл говорит,
  КАК работать: порядок шагов, детекторы, приёмка.
- **Доки** — `games/make-a-mess/docs/*.md` — контракты и уроки с числами.
  Док говорит, ЧТО истинно: законы, измеренные значения, грабли и их
  происхождение. Скилл ссылается на док, а не дублирует его.

Исключение: изолированная object study живёт целиком в скилле
`reference-faithful-object-study` (SKILL.md + references/), парного дока нет.

## Порядок чтения для новичка

0. `shared-tree-discipline.md` и `run-and-verify.md` — до первой правки:
   дерево общее, а наблюдение надо уметь получить.
1. `physical-architecture-guide.md` — планка качества и карта истины.
1a. `joint-canon.md` — до первой сборки узла из двух тел, каким бы ни был
   домен: закон стыка один и нарушается одинаково в грунте, на фасаде и в
   салоне вагона.
2. Скилл своего домена (по триггерам из его description).
3. Парный док-плейбук из таблицы выше — целиком.
4. Бриф конкретного мира или объекта, если правка привязана к месту.
5. `docs/SCENE-AUTHORING.md` и `docs/ARCHITECTURE.md` (в корне репо) — модель
   данных сцены и рантайм.

## Правило владения

У каждой темы ровно один док-владелец. Не заводить новый док, если тема уже
имеет владельца, — дописывать секцию во владельца. Дубликаты запрещены:
второй текст о том же законе неизбежно расходится с первым.

Куда писать новый урок (примеры):

- стык двух тел, щель, копланарность, тайлинг, z-fighting, бюджет глубины →
  `joint-canon.md` (домен кросс-доменный: и грунт, и фасад, и мебель вагона);
- форма фасада, проёмы, остекление, кривые оболочки →
  `architectural-authoring.md`;
- цена кадра, деградация, бюджеты → `performance-lessons.md`;
- новый материал или ступень урона → `destruction-lessons.md`;
- небо, вода, свет мира, туман → `environmental-rendering-lessons.md`;
- поведение жителей → `village-inhabitants-lessons.md`;
- грабли решателя при сборке машины →
  `.claude/skills/vehicle-authoring/references/assembly.md`;
- управление машиной, автопилот, стадии рейса, швартовка/посадка →
  `vehicle-control-lessons.md`;
- физика носителя (масса, подъём, Rapier-тело, удар) →
  `airborne-vehicle-dynamics.md`;
- рецепт кадра, dev-хук, инструмент замера, враньё headless →
  `run-and-verify.md`;
- git, соседние агенты, чужая незакоммиченная работа →
  `shared-tree-discipline.md`.
