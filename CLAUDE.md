# playgate — как здесь работать

Этот файл читает каждый агент, приходящий в репозиторий, на любой из машин. Он про
устройство работы, а не про предметную область: правила миров, транспорта, разрушения и
архитектуры живут в скиллах `.claude/skills/` и документах `games/make-a-mess/docs/`.

## Проект разрабатывается с двух машин одновременно

Обе машины — рабочие. Деление идёт **по весу задачи, а не по ролям**.

Ниже — короткая сводка. Полный плейбук параллельной работы — скилл
`.claude/skills/parallel-work/SKILL.md`: куда отправить задачу, как передать
прогон или целую задачу на Windows, как поговорить с агентом на Mac через
почтовый ящик, как развести сессии по worktree и что проверять, принимая чужую
работу. **Прочитать его до начала долгой или широкой работы**, а не после того,
как что-то разошлось.

| | Windows (`igorki-primary`) | Mac |
|---|---|---|
| Память / диск | 40 ГБ / 170 ГБ | 8 ГБ / около 5 ГБ |
| Что берёт | длинные и тяжёлые задачи по коду, полный прогон, сборка, `next dev`, съёмка кадров, несколько worktree | задачи поуже, проектирование, ревью, документы |

**На Mac не запускают** `npm ci`, `npm run build`, полный `npm test` и `next dev` — не из
принципа, а по железу. Тяжёлое не отменяется, а передаётся:

```
ssh igor@100.108.230.70 "winrun npm test"
ssh igor@100.108.230.70 "winrun npx tsc --noEmit"
ssh igor@100.108.230.70 "winrun claude -p 'задача'"
```

`winrun` — обёртка внутри WSL-дистрибутива `Debian` на Windows-хосте; она запускает команду
нативным windows-процессом в репозитории, поэтому скорость сборки не страдает.

Последняя форма важна: на Windows работает и headless-агент, то есть туда передают **целые
задачи по коду**, а не только прогоны. Обратное невозможно — на Mac учётные данные лежат в
Keychain, недоступном неинтерактивной сессии, и `claude -p` по SSH падает с `Not logged in`.
Агентов передают только в сторону Windows.

### Главная ловушка: у Windows своя рабочая копия

`winrun` работает в `C:\Users\IgorKirisyuk\cursor\playgate`, а не в файлах Mac.
Незапушенная правка для него не существует — прогон пройдёт по старому коду и **вернёт
зелёный, ничего не проверив**. Перед передачей тяжёлого прогона правки должны быть
закоммичены и запушены, а Windows-сторона обязана сделать `git pull`.

Отсюда же общее правило: начиная работу, синхронизируйтесь с origin и не сидите на
незакоммиченных правках, если вторая машина может взяться за тот же участок. Параллельную
работу разводить по подсистемам (мир / транспорт / жители / разрушение), а не по принципу
«кто успел».

**Дерево общее — читайте `games/make-a-mess/docs/shared-tree-discipline.md` до первой
git-команды.** Там список запрещённых операций и способ снять базовую линию через
`git worktree` вместо `git stash`. Это не теория: `git stash` в общем дереве уже стоил
185 файлов чужой незакоммиченной работы.

Как получить наблюдение — запуск, гейт условий, детерминированный кадр по CDP, dev-хуки,
чему headless верить нельзя и гигиена браузера — `games/make-a-mess/docs/run-and-verify.md`.

## Сборка и тесты

```
npm ci               # только так; npm install перепишет лок
npm run typecheck    # tsc --noEmit, 8 секунд
npm run test:affected  # только тесты, зависящие от правки
npm test             # = next build + весь набор, 6 минут
```

### Что гонять и когда

Полный прогон идёт около шести минут. Гонять его на каждую мелочь — не
осторожность, а потеря времени: **тест, который не импортирует изменённый файл
ни прямо, ни через цепочку, упасть от него не может по построению.** Отсюда
три уровня, и выбирает между ними ВЕС ПРАВКИ, а не настроение:

| когда | что | цена |
|---|---|---|
| каждая правка, коммит И ПУШ | `npm run typecheck` + `npm run test:affected` | 8 с + секунды-минута |
| правка, которую отбор не видит | `npm test` целиком | 6 минут |
| перед передачей работы второй машине | `npm test` целиком | 6 минут |

**Отбор и есть гейт, в том числе перед пушем.** Полный прогон не назначается
«на всякий случай»: если правка тронула общий контракт, отбор сам вытянет
тридцать-сорок файлов, а если не тронула — гонять остальные сто тридцать
незачем, они физически не могут упасть. Первая редакция этого раздела ставила
`npm test` на каждый пуш, и Igor это снял сразу: правило, которое всё равно
приводит к шести минутам, ничего не экономит.

Полный прогон остаётся ровно там, где отбору верить нельзя (см. границы ниже)
и где работа уходит из рук.

`npm run test:affected` строит граф импортов от каждого теста и запускает те,
чьё замыкание пересеклось с изменёнными файлами (`tools/affected-tests.mjs`).
Замер: правка чистого модуля — 2 теста и 19 секунд; правка `vehicleFrames` —
37 тестов, и это правильный ответ, а не недостаток отбора.

Границы, за которыми отбору верить нельзя:

- он видит только **статические импорты**. Правка данных, которые читаются не
  импортом, в отбор не попадёт;
- он ничего не знает про **React-компоненты**: `VehicleFrameSystem` и
  `MakeAMessGame` тестами не покрыты вовсе, и обе поломки запуска боевой
  задачи (08.08.2026) жили именно там. Правка в компоненте — это повод
  вынести решение в чистую функцию и покрыть ЕЁ, а не повод прогнать всё;
- он не заменяет **сборку**: `next build` ловит своё. Но тайпчек за 8 секунд
  ловит почти то же самое, поэтому сборка нужна перед пушем, а не на каждом
  шаге.

Планка (06.08.2026): **1547 тестов, 1544 зелёных, 3 красных**; на 08.08.2026 —
1625 / 1622 / 3; на 09.08.2026 — **1765 / 1762 / 3**. Считать надо не «зелено
ли», а «те ли три» (список ниже).

Канонический пакетный менеджер — **npm**. `pnpm-lock.yaml` и `pnpm-workspace.yaml` в
репозитории — мусор: воркспейс там не описан, под-пакетов нет, а скрипт `test` сам вызывает
`npm run build`.

`npm run build:firebase` написан в POSIX-синтаксисе (`FIREBASE_STATIC_EXPORT=1 next build`)
и на Windows не запускается. Деплой — только с Mac.

### Красные тесты, которые чинить НЕ надо

Планка на 06.08.2026: **1547 тестов, 1544 зелёных, 3 красных**. Все три — принятые решения
Igor, а не поломки. Не чинить их и не поднимать вопрос заново:

- `villagers cannot walk through the world` — житель проходит сквозь створку менее чем в
  проценте случаев (0.46% против бюджета 0.2%). Вердикт: «милая неисправность».
- `деревня: описание поселения ссылается только на то, что в нём есть` —
  `settlement-plan.test.mjs:28`, роль `housekeeper` не объявлена в поселении.
- `деревня: население живёт по своему поселению, а не по чужому` —
  `settlement-plan.test.mjs:70`, роль `hand` не из этого поселения.

**Любой четвёртый красный — регрессия.** Это единственный смысл, в котором прогон остаётся
сигналом: считайте не «зелено ли», а «те ли три».

## Скиллы

`.claude/skills/` — точка входа; правила канона живут в `games/make-a-mess/docs/`. Скилл
ссылается на документ, а не пересказывает его. Не переносите правила из docs обратно в
`SKILL.md` — это отыграет назад проделанное слияние дублей.

Скиллы держат **только в репозитории**. Одноимённый скилл в пользовательском слое
(`~/.claude/skills/`, `~/.codex/skills/`) молча перекрывает репозиторный, и две машины
начинают выполнять разные инструкции при одинаковом имени. Обнаружив такой дубликат — не
удалять сразу, сперва сверить: в нём могут оказаться уникальные материалы.

Описание в YAML-frontmatter писать **блочным скаляром**:

```yaml
description: >-
  Текст описания, который спокойно содержит двоеточия: вот такие,
  и переносится на сколько угодно строк с отступом ровно в 2 пробела.
```

Плоский скаляр не может содержать `: ` (двоеточие с пробелом). Ошибка коварна тем, что
загрузчики разной строгости ведут себя по-разному: на одной машине скилл теряет ВСЕ триггеры
и молча не срабатывает, на другой грузится целиком. Проверяется тестом
`tests/skill-frontmatter.test.mjs`.

## Мелочи, стоившие времени

- `tsconfig.json` исключает `out` — иначе тайпчек уходит в выхлоп статического экспорта и
  сборка падает с ошибкой в собственном артефакте.
- Снятие палитры с фотографии — `node .claude/skills/world-building/scripts/palette.mjs
  --grid 8 photo.jpg`. Работает на обеих платформах (`sharp`, уже в зависимостях).
- `scripts/object-lab-capture.mjs` ищет Chrome на обеих платформах; путь можно задать
  через `PLAYGATE_CHROME`.
- Скрипты PowerShell писать в ASCII: Windows PowerShell 5.1 читает `.ps1` без BOM как ANSI,
  и не-ASCII символы ломают разбор — длинное тире превращается в кавычку и рвёт строку.
